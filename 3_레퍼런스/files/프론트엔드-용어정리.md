# 프론트엔드 용어 정리

비전공자 기준으로 정리했습니다. 용어마다 "무엇인지"와 "무슨 일을 하는지"를 먼저 적고, 당신 프로젝트(바닐라 3D 사이트를 React로 옮기는 작업)와 관련된 건 메모를 달았습니다.

---

## A. 웹의 기본 구조

**프론트엔드(Front-end)**
사용자가 화면에서 직접 보고 누르는 부분이다. 버튼, 글자, 색, 움직임이 전부 프론트엔드다.

**백엔드(Back-end)**
사용자 눈에 안 보이는 부분이다. 데이터 저장, 로그인 처리, 계산을 담당한다.

**클라이언트(Client)**
사용자의 기기와 브라우저를 가리킨다. 당신 PC, 방문자의 휴대폰이 클라이언트다.

**서버(Server)**
요청을 받아 파일이나 데이터를 보내주는 컴퓨터다. 사이트 주소를 입력하면 서버가 HTML 파일을 보낸다.

**브라우저(Browser)**
크롬, 사파리 같은 프로그램이다. HTML·CSS·JavaScript를 읽어 화면으로 그려준다.

---

## B. 3대 핵심 언어

프론트엔드는 이 세 가지가 기본이다. 역할이 명확히 나뉜다.

**HTML (HyperText Markup Language)**
웹페이지의 구조와 내용을 정의하는 언어다. "여기는 제목, 여기는 문단, 여기는 이미지"를 표시한다. 내용만 담당하고 디자인이나 동작은 담당하지 않는다.

**CSS (Cascading Style Sheets)**
화면의 모양을 담당하는 언어다. 색, 크기, 위치, 간격, 글꼴을 지정한다. HTML이 정한 내용에 디자인을 입힌다.

**JavaScript (JS)**
동작과 상호작용을 담당하는 언어다. 버튼을 누르면 창이 뜨고, 스크롤하면 화면이 바뀌는 일은 전부 JavaScript가 한다.
> 메모: 당신 사이트의 스크롤 작동과 3D 움직임은 JavaScript로 짜여 있다.

---

## C. HTML 용어

**요소(Element)와 태그(Tag)**
요소는 HTML을 이루는 한 덩어리다. 태그는 그 요소를 표시하는 기호다. `<p>안녕</p>`에서 `<p>`와 `</p>`가 태그이고, 전체가 하나의 요소다.

**속성(Attribute)**
요소에 추가 정보를 붙이는 값이다. 이미지 요소에 주소를 지정하거나, 요소에 이름표를 붙일 때 쓴다.

**DOM (Document Object Model)**
브라우저가 HTML을 읽어 머릿속에 만든 구조다. JavaScript는 이 DOM을 통해 화면 요소를 찾고 바꾼다.
> 메모: "DOM 조작"은 JavaScript가 화면의 글자나 요소를 실시간으로 바꾸는 작업을 뜻한다.

---

## D. CSS 용어

**선택자(Selector)**
디자인을 적용할 대상을 고르는 문법이다. "모든 제목" 또는 "이 버튼 하나"처럼 범위를 지정한다.

**속성(Property)과 값(Value)**
무엇을 어떻게 바꿀지 정하는 한 쌍이다. `color: red`에서 `color`가 속성, `red`가 값이다.

**반응형 디자인(Responsive)**
화면 크기에 따라 레이아웃이 자동으로 바뀌는 방식이다. PC에서 가로 3칸이던 게 휴대폰에서 세로 1칸으로 바뀐다.

**미디어 쿼리(Media Query)**
반응형을 구현하는 CSS 문법이다. "화면이 600px보다 좁으면 이렇게 바꿔라"를 지정한다.

**Flexbox / Grid**
요소를 가로세로로 배치하는 CSS 기능이다. Flexbox는 한 줄 정렬, Grid는 격자 배치에 쓴다.

**전처리기(Sass / SCSS)**
CSS를 더 편하게 쓰게 해주는 확장판이다. 변수와 반복을 지원한다. 최종적으로는 일반 CSS로 변환된다.

**Tailwind CSS**
미리 만들어둔 짧은 클래스 이름으로 디자인하는 도구다. 별도 CSS 파일을 적게 쓰고 HTML 안에서 바로 디자인을 지정한다.

---

## E. JavaScript 용어

**변수(Variable)**
값을 담아두는 이름표다. 숫자나 글자를 저장해두고 나중에 꺼내 쓴다.

**함수(Function)**
정해진 동작을 묶어둔 단위다. 한 번 만들어두면 필요할 때마다 호출해서 같은 동작을 실행한다.

**이벤트(Event)**
사용자의 행동이다. 클릭, 스크롤, 키 입력이 전부 이벤트다. JavaScript는 이벤트가 일어나면 정해둔 함수를 실행한다.
> 메모: 당신 사이트의 "스크롤하면 3D가 움직인다"는 스크롤 이벤트에 함수가 연결된 구조다.

**API (Application Programming Interface)**
프로그램끼리 정보를 주고받는 약속이다. 날씨 API를 호출하면 현재 날씨 데이터를 받아온다.

**비동기(Asynchronous) / async, await**
오래 걸리는 작업을 기다리는 동안 다른 일을 멈추지 않게 하는 방식이다. 데이터를 받아오는 동안 화면이 멈추지 않게 한다.

**JSON (JavaScript Object Notation)**
데이터를 정리해 담는 글자 형식이다. 이름·값 쌍으로 되어 있어 사람과 프로그램 모두 읽기 쉽다.

---

## F. 라이브러리와 프레임워크

**라이브러리(Library)**
자주 쓰는 기능을 미리 만들어둔 도구 모음이다. 필요한 기능만 골라 쓴다.

**프레임워크(Framework)**
전체 뼈대와 규칙까지 정해주는 큰 도구다. 라이브러리보다 강제하는 구조가 많다. 차이는 "내가 도구를 부른다"(라이브러리) 대 "도구의 규칙 안에서 내가 짠다"(프레임워크)이다.

**React**
화면을 작은 조각으로 나눠 만드는 JavaScript 라이브러리다. 페이스북이 만들었고 가장 널리 쓰인다.
> 메모: 당신이 옮기려는 목적지다.

**컴포넌트(Component)**
화면을 이루는 재사용 가능한 조각이다. 버튼 하나, 카드 하나를 컴포넌트로 만들어 여러 곳에 다시 쓴다. React의 핵심 단위다.

**State(상태)**
컴포넌트가 기억하는 현재 값이다. 값이 바뀌면 화면이 자동으로 다시 그려진다. 메뉴가 열림/닫힘처럼 변하는 정보가 state다.

**Props**
부모 컴포넌트가 자식 컴포넌트에 넘겨주는 값이다. 같은 버튼 컴포넌트에 글자만 다르게 넘길 때 props를 쓴다.

**JSX**
React에서 HTML처럼 생긴 코드를 JavaScript 안에 쓰는 문법이다. 화면 구조와 동작을 한 파일에 같이 적는다.

**Vue, Angular**
React와 같은 목적의 다른 프레임워크다. 셋 중 하나를 고른다. 당신은 React 방향이므로 이름만 알아두면 된다.

---

## G. 3D 관련

**WebGL**
브라우저에서 3D 그래픽을 그리는 기술이다. 직접 다루기 어려워서 보통 아래 라이브러리를 통해 쓴다.

**Three.js**
WebGL을 쉽게 쓰게 해주는 JavaScript 라이브러리다. 웹에서 3D 오브젝트를 만드는 표준에 가깝다.
> 메모: 당신 사이트의 3D는 Three.js로 만들었을 가능성이 높다. (확인 필요)

**react-three-fiber (R3F)**
Three.js를 React 방식으로 쓰게 해주는 라이브러리다. 3D 오브젝트를 컴포넌트로 다룬다.
> 메모: React로 옮기면 Three.js 코드가 보통 이걸로 바뀐다.

**Canvas**
3D나 그림을 그리는 화면 영역이다. Three.js는 이 Canvas 위에 3D를 그린다.

---

## H. 개발·빌드 도구

**Node.js**
JavaScript를 브라우저 밖에서 실행하는 프로그램이다. React 같은 도구를 설치하고 돌리려면 필요하다.
> 메모: React 버전을 PC에서 띄워보려면 먼저 이게 깔려 있어야 한다.

**npm (Node Package Manager)**
필요한 라이브러리를 내려받아 설치하는 도구다. Node.js와 함께 깔린다.

**패키지(Package)**
npm으로 설치하는 라이브러리 한 덩어리다. React, Three.js 모두 패키지로 설치한다.

**번들러(Bundler) — Vite, Webpack**
여러 파일을 묶어 브라우저가 읽을 수 있는 형태로 만드는 도구다. Vite가 요즘 표준이고 빠르다.

**빌드(Build)**
작성한 코드를 실제 배포용 파일로 변환하는 과정이다. React 코드는 그대로 브라우저에서 안 열리고 빌드를 거쳐야 한다.
> 메모: 바닐라 사이트는 파일을 더블클릭하면 열리지만, React는 빌드 또는 개발 서버가 필요해 그냥 안 열린다. 이 차이가 비개발자에게 첫 장벽이다.

**트랜스파일(Transpile)**
새 문법이나 JSX를 브라우저가 이해하는 옛 문법으로 바꾸는 작업이다. 빌드 과정에 포함된다.

**개발 서버(Dev server)**
작업 중인 사이트를 PC에서 임시로 띄워 확인하는 도구다. 코드를 고치면 화면에 바로 반영된다.

## I. 기타 자주 나오는 말

**렌더링(Rendering)**
코드를 실제 화면 그림으로 그려내는 과정이다.

**마크업(Markup)**
태그로 내용의 구조를 표시하는 것이다. HTML이 마크업 언어다.

**바닐라(Vanilla)**
프레임워크 없이 순수 HTML·CSS·JavaScript만 쓴 상태다.
> 메모: 지금 당신 사이트가 바닐라다.

**Git / GitHub**
Git은 코드 변경 기록을 저장하는 도구다. GitHub는 그 코드를 온라인에 보관·공유하는 사이트다. 작업 전 원본을 안전하게 보관할 때 쓴다.

---

## 우선순위 메모

당신 작업(바닐라 3D → React)에서 먼저 익힐 용어는 이것들이다.

1. **컴포넌트, State, Props, JSX** — React의 핵심 4개
2. **Three.js, react-three-fiber** — 3D가 어떻게 옮겨지는지
3. **Node.js, npm, 빌드, 개발 서버** — React 버전을 PC에서 띄우는 데 필요
4. **이벤트, DOM 조작** — 스크롤 동작의 원리

나머지는 작업 중 마주칠 때 이 노트에서 찾아보면 된다.
